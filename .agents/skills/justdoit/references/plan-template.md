# Шаблон Плана

Используй этот файл как базовую форму для `plans.md` или эквивалентного план-файла в репозитории.

## Принципы

- План обязателен почти всегда.
- Этапы идут по зависимостям, а не по красоте рассказа.
- Каждый этап должен быть достаточно маленьким для одного сфокусированного цикла.
- У каждого этапа должны быть критерии готовности и команды проверки.
- Если меняется поведение, это должно быть явно видно в плане.

## Правила Адаптации

- Если в репозитории уже есть `PLAN.md`, `plans.md` или другой принятый путь, сохраняй его.
- Если задача большая, сначала дели на фазы, затем на этапы внутри активной фазы.
- Если задача неоднозначна, используй блок `Варианты Решения`, но только когда сравнение реально влияет на выбор.
- Если задача слишком велика для прямого детального плана, сначала заполняй `Верхнеуровневая Декомпозиция`, а не расписывай все части одинаково подробно.
- Если задача заметно влияет на пользовательский сценарий, внешний контракт или архитектуру, заполняй `Дизайн-Checkpoint` до запуска исполнения.
- Если план уже существует, сохраняй завершенные этапы и переписывай только затронутые части.
- Если задача про исправление бага, первый активный этап должен либо воспроизводить проблему, либо явно фиксировать, почему надежное воспроизведение уже существует.
