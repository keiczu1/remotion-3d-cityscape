# Использование Three.js и React Three Fiber в Remotion

Соблюдай обычные best practices для React Three Fiber и Three.js.
Дополнительно нужно соблюдать следующие правила, специфичные для Remotion:

## Подготовка

Сначала убедись, что установлен пакет `@remotion/three`.
Если его нет, используй одну из следующих команд:

```bash
npx remotion add @remotion/three # If project uses npm
bunx remotion add @remotion/three # If project uses bun
yarn remotion add @remotion/three # If project uses yarn
pnpm exec remotion add @remotion/three # If project uses pnpm
```

## Использование ThreeCanvas

Любой 3D-контент нужно рендерить внутри `<ThreeCanvas>` и с корректным светом.
У `<ThreeCanvas>` обязательно должны быть props `width` и `height`.

```tsx
import { ThreeCanvas } from "@remotion/three";
import { useVideoConfig } from "remotion";

const { width, height } = useVideoConfig();

<ThreeCanvas width={width} height={height}>
  <ambientLight intensity={0.4} />
  <directionalLight position={[5, 5, 5]} intensity={0.8} />
  <mesh>
    <sphereGeometry args={[1, 32, 32]} />
    <meshStandardMaterial color="red" />
  </mesh>
</ThreeCanvas>;
```

## Никаких анимаций вне `useCurrentFrame()`

Шейдеры, модели и другие 3D-элементы не должны анимироваться сами по себе.
Любая анимация допустима только если она управляется через `useCurrentFrame()`.
Иначе при рендере появится мерцание.

Использовать `useFrame()` из `@react-three/fiber` запрещено.

## Анимация через `useCurrentFrame()`

Для анимации используй `useCurrentFrame()`.

```tsx
const frame = useCurrentFrame();
const rotationY = frame * 0.02;

<mesh rotation={[0, rotationY, 0]}>
  <boxGeometry args={[2, 2, 2]} />
  <meshStandardMaterial color="#4a9eff" />
</mesh>;
```

## Использование `<Sequence>` внутри `<ThreeCanvas>`

У любого `<Sequence>` внутри `<ThreeCanvas>` prop `layout` должен быть равен `none`.

```tsx
import { Sequence } from "remotion";
import { ThreeCanvas } from "@remotion/three";

const { width, height } = useVideoConfig();

<ThreeCanvas width={width} height={height}>
  <Sequence layout="none">
    <mesh>
      <boxGeometry args={[2, 2, 2]} />
      <meshStandardMaterial color="#4a9eff" />
    </mesh>
  </Sequence>
</ThreeCanvas>;
```

## Performance-инварианты для 3D-сцен

Повторяющиеся particle, weather, confetti и другие массовые 3D-элементы не должны рендериться как сотни отдельных прозрачных `<mesh>`.
Для таких систем по умолчанию используй batching, shared geometry/material и `instancedMesh`, если визуальная задача это допускает.

Если в сцене есть camera remap, slowdown или отдельная timeline-функция для камеры, все camera-driven состояния обязаны жить в той же системе времени:
- `focusedIndex`;
- detail/render window;
- preload;
- visibility/presentation gates.

Нельзя считать камеру по remapped timeline, а детализацию, reveal или visibility по raw display frame: это приводит к исчезновениям и рывкам в flyover-сценах.

Для широких overview/flyover-кадров одного только index/focus window недостаточно.
Если объект или карточка уже реально попали в кадр, у сцены должен быть projection-aware fallback, который не даёт таким объектам падать в `minimal` только потому, что они далеко от текущего `focusedIndex`.

В тяжёлых per-frame циклах по множеству инстансов не используй `random(...frame)` как основной источник вариативности.
Для пульсаций, дождя, салюта и похожих систем лучше заранее фиксировать seeds/phases и на кадре считать только лёгкую детерминированную математику.

Если FPS проседает не везде, а на длинном участке ролика, сначала ищи sustained hotspot, который живет много секунд подряд.
Редкие spike-слои вроде lightning, flash или payoff-вспышек имеет смысл облегчать после того, как снята постоянная нагрузка.

Перед любым micro-fix сначала определи тип нагрузки:
- scene math / projection / visibility;
- WebGL draw calls / shaders / transparent layers;
- DOM / CSS overlay / paint / compositing;
- asset decode / texture upload / preload miss;
- bundler / cache / toolchain.

Если проблема проявляется в `Studio` или browser playback, не считай это автоматически проблемой object count или 3D-мира.
В смешанных сценах `ThreeCanvas + DOM overlay` overlay нужно рассматривать как отдельный sustained hotspot и проверять отдельно от WebGL-слоя.

Нельзя ограничиваться только frame-level profiling, если сцена уже использует несколько render-слоев.
Сначала установи уровень корневой причины, потом оптимизируй конкретный hot-кадр.
