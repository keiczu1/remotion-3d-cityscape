# Workflow Plans

## Назначение

`docs/workflow/` хранит рабочие планы изменений самого workflow, аудиты документации и implementation-notes по улучшению процесса.

Эта папка не является каноном и не владеет production-правилами.

## Что здесь допустимо

- планы по оптимизации workflow;
- карты дублей и зон разрастания контекста;
- change-plans для skills, templates, validator и навигационного слоя;
- промежуточные аудиты перед переносом итогов в активный контур.

## Что здесь недопустимо

- держать единственную актуальную версию правила;
- менять процесс только внутри этой папки без синхронизации канона;
- ссылаться на файлы из этой папки как на верховный source-of-truth.

## Куда должны попадать итоговые правила

После реализации и проверки изменения должны быть отражены в владельцах правил:

- `AGENTS.md`
- `docs/README.md`
- `docs/canon/`
- `projects/README.md`
- `docs/templates/`
- `.agents/skills/`
- `scripts/validate-ranking-build-plan.ts`

## Именование

Для новых рабочих планов используй формат:

- `YYYY-MM-DD-short-topic.md`

Такой файл должен описывать цель изменения, границы, инварианты без деградации качества и шаги внедрения.
