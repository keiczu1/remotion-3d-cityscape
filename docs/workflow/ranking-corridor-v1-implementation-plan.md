# Ranking Corridor: V1 План Реализации

**Дата:** 2026-03-18

## Назначение

Этот файл хранит только текущий статус внедрения `v1`.

Он нужен, чтобы в любой момент быстро ответить:

- где мы сейчас;
- что уже сделано;
- что осталось;
- какой следующий практический шаг;
- по каким критериям закрывается пилот.

Стабильные правила системы живут в:

- `docs/canon/ranking-corridor-working-mode.md`
- `docs/workflow/ranking-corridor-workflow-implementation-plan.md`

## Текущий статус

### Уже выполнено

- Этап 1: `ranking-corridor-launch` skill — выполнен.
- Этап 2: шаблоны `launch-card`, `asset-manifest`, `review-notes` — выполнены.
- Этап 3: `ranking-corridor-production` skill — выполнен.
- Навигация docs, канон и registry приведены в рабочий вид.

### Еще не закрыто

## Planning checkpoint для ИИ

Перед следующим нетривиальным шагом ИИ должен коротко проверить:

- на каком мы этапе;
- что уже готово;
- что еще не сделано;
- какой следующий логичный шаг;
- какие docs надо обновить по итогам шага;
- какая проверка или какой review закрывают шаг.

## Следующий шаг

Следующий правильный шаг:

1. Взять новую тему.
2. Пройти pilot-pass по полному пути `topic -> question-pack -> launch-card -> asset-manifest -> preview-gate -> full project -> final approval -> library audit`.
3. После пилота провести `post-pilot decision`.

## Checklist пилота

Во время пилота должны быть пройдены такие этапы:

1. Пользователь дает новую тему одной фразой.
2. `ranking-corridor-launch` задает один пакет вопросов.
3. После ответа собирается `launch-card`.
4. `ranking-corridor-production` создает project-container и `asset-manifest`.
5. Делается `preview-gate`.
6. После review предпросмотра допускается полный build.
7. Фиксируется финальный статус проекта.
8. После финального статуса запускается аудит библиотеки.

## Acceptance checklist пилота

Пилот считается пройденным только если одновременно выполнено все ниже:

- новый проект стартовал без повторного длинного объяснения жанра;
- ИИ задал один пакет вопросов и остановился на `launch-card`;
- production-ветка дошла до `preview-gate` раньше полного build;
- `review-notes.md` использовался как единый файл для `Предпросмотра`, `Финального утверждения` и `Аудита библиотеки`;
- project-container соответствовал структуре из `projects/README.md`;
- после финального статуса был выполнен аудит библиотеки;
- по итогам пилота стало понятно, нужны ли правки в docs, skills или templates.

## Post-pilot decision

После пилота нужно отдельно решить:

- достаточно ли `v1` в текущем виде;
- нужно ли усиливать `src/lib/ranking-corridor/`;
- нужен ли дополнительный generator;
- нужен ли отдельный skill сверх `launch` и `production`;
- какие модули реально заслужили перенос в библиотеку.
